## v0.2.1 授权工作台

打开 [授权工作台](http://127.0.0.1:8018/tools/auth-bridge)，选择已登记的账号，可检查会话、额度与设备数，或从工作区列表进入团队详情。固定代理与内核实际出口能匹配时，工作台使用该出口检测。其他固定代理账号可在「查看账号详情」使用原有检测入口。

「模型评测」包含逻辑题和 SVG 动画题。账号评测由内嵌 Bridge 执行。选择「自己的 API」时，浏览器使用填写的地址和密钥直接请求模型服务，服务需允许浏览器跨域访问。用量按所选服务计算。

工作台也可直接打开[协议登录](http://127.0.0.1:8018/accounts?assist=protocol)。本机运行 `./scripts/local-service.sh start` 即可启动 Team48 和其托管的内核。

## 首次登录

1. 打开 `http://127.0.0.1:8018`。
2. 用户名为 `admin`。
3. 初始随机密码见项目根目录 `.env` 的 `ADMIN_PASSWORD`，不要把整个文件发给别人。
4. 登录后可在「设置」底部的「后台账号」修改密码。

终端查看初始登录信息：

```bash
cd /Users/a1/Projects/48team-manager-main
rg '^ADMIN_(USERNAME|PASSWORD)=' .env
```

管理员密码首次启动后以哈希形式保存在数据库中。网页改密后，`.env` 中仍是初始值；仅修改 `.env` 的密码不能覆盖已有后台密码。

## 登记第一个团队

建议先选择自己有管理权限、不会与生产自动化同时操作的测试团队。

1. 进入「账号与团队」，点击右上角「登记」菜单，选择「登记团队」。
2. 填入已有团队的母号邮箱。不要先用「登记账号」登记同一个母号，否则会被重复邮箱检查拦截。
3. 代理是可选项。未配置 Sub2API 时会提示「代理目录读取失败」，当前版本仍可继续生成授权链接，未选代理即使用直连。
4. 点击「生成授权链接」，再点击「打开授权」，使用对应母号完成登录。
5. 跳转到 `http://localhost:1455/auth/callback?...` 后，将地址栏中包含 `code` 和 `state` 的完整地址贴回本项目「回调地址」。
6. 点击「完成授权」。这只登记已有团队，不会创建或购买新团队。
7. 登记后在团队卡片上点击「同步本团队」，读取该团队的成员及邀请状态；需要查看额度时使用「立即检查」或账号详情中的检查入口。
8. 进入「任务记录」查看执行进度和失败原因。刷新或关闭网页不等于取消后台任务。

手动回填流程不要求本项目监听 1455 端口，所以回调页可能显示无法连接；仍可复制完整回调地址。回调包含敏感授权信息，不要发到聊天、工单或截图中。授权过期后重新生成链接。

如果当前网络无法直连授权或官方接口，需要先配置本机可用的网络路径，或接入 Sub2API 代理目录。代理选项不会自动给手动打开的普通浏览器配置系统代理。

「登记账号」只创建本地档案，不会注册远端账号、邀请入组或自动获得授权。

## 可选外部服务

在「设置」中点击相应服务的「编辑」，填写配置，按需「检测」，最后点击「保存设置」。检测使用当前输入，不代表已经保存。

| 服务 | 需要填写 | 作用 |
| --- | --- | --- |
| Sub2API | 本机可访问的地址，以及 Admin API Key 或管理员邮箱和密码 | 读取代理目录、同步账号和用量 |
| iCloud HME | 本机可访问的 HME 服务地址、服务 Token、账号 ID | 为留空邮箱的流程分配未占用别名 |
| 临时邮箱 | Cloudflare 邮箱 API 地址、邮箱地址、管理员密码 | 读取注册或授权所需的邮件验证码 |
| 手机号池 | 在「手机号」页导入号码与接码链接 | 在需要短信验证的流程中提供号码 |

号码导入格式，每行一条：

```text
+15551234567----https://sms.example/by_key?key=REPLACE_ME
```

这些资源不是启动和登录后台的前提；自动注册、补位、自动重授权等流程则可能需要完整配置。

注意：

- 设置页可能显示原项目的 Docker 服务名，例如 `sub2api-canary`、`icloud-hme`。这些不是本机部署好的服务，也通常不能从 Mac 直接解析。应使用获准且本机可达的服务地址，不要为此暴露数据库或修改生产容器网络。
- HME 占用信息只认 VPS 上 HME 服务维护的 `accounts.json` 本地标签和租约，不使用本项目的 `data/accounts.json` 作为占用库，也不直接修改 Apple 原生标签。
- 不要让本机和 VPS 同时对同一 Apple 账号自动创建别名。
- 不要直接复制生产数据库或让两套自动化同时管理同一批令牌、成员和席位。
- 「邀请」「移除」「轮转」「推送 Sub2API」有真实远端副作用，不是预览操作。首次使用先保持自动化关闭。
- 自动重授权还有 `.env` 的部署总开关，目前为 `AUTO_REAUTH_ENABLED=False`。只勾选网页开关不会解除这个限制。

## 服务管理

先进入项目目录：

```bash
cd /Users/a1/Projects/48team-manager-main
```

按需执行其中一条：

```bash
./scripts/local-service.sh status
./scripts/local-service.sh start
./scripts/local-service.sh restart
./scripts/local-service.sh stop
./scripts/local-service.sh logs
```

`stop` 只卸载本次登录会话中的服务，下一次登录仍会自动启动。需要长期禁止登录自启时执行：

```bash
launchctl disable "gui/$(id -u)/local.team48.manager"
./scripts/local-service.sh stop
```

恢复登录自启并启动：

```bash
launchctl enable "gui/$(id -u)/local.team48.manager"
./scripts/local-service.sh start
```

服务配置文件为 `~/Library/LaunchAgents/local.team48.manager.plist`；日志在项目 `logs/` 下。
修改 `.env` 后需要重启；网页保存的服务设置保存在数据库中。端口由 LaunchAgent 的启动参数固定为 8018，只改 `.env` 的 `APP_PORT` 不会改变监听端口。

停止或重启前先查看「任务记录」，等待重要任务完成。重启不会撤回已经发出的邀请或其他远端操作，也不要假定浏览器任务会自动恢复。

不要移动或重命名项目目录，否则 LaunchAgent 和虚拟环境中的绝对路径将失效。

## 数据和备份

- `.env` 包含加密密钥和初始密码，文件权限为仅当前用户读写。
- `data/team48.db` 保存账号、配置和任务。
- `data/chrome-profiles/` 在使用浏览器流程后保存独立账号档案。
- 备份时应同时保留 `.env` 和整个 `data/`。丢失或随意修改 `SECRET_KEY` 会导致已存凭据无法解密。
- SQLite 正在运行时可能存在 WAL 文件，不要只复制主 `.db` 文件作为完整备份；先停止本项目服务再备份，或使用 SQLite 的在线备份接口。

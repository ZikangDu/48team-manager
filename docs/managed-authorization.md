# 母号、子号与协议授权

## 推荐流程

1. 打开授权工作台，或「登记团队 → 账密＋2FA 批量导入」，输入账号凭据并选择代理。无需先手动登记同一邮箱或粘贴 OAuth 回调。
2. 授权成功并保存后，后台自动读取该授权对应工作区的官方角色，并刷新官方额度。
3. 官方非个人工作区的 Owner 自动识别为母号，登记本地团队并同步成员；Member / Admin 识别为成员账号并关联对应团队。普通成员不会自动获得母号权限。
4. 已同步成员按邮箱匹配已登记的子号；尚无本地凭据的成员保留为官方未接入。以后导入子号时同样会匹配。子号可选择继承母号的固定代理，或继承已经官方验证可用的明确直连出口。

成员名单只能提供成员身份、角色和邀请状态，不包含子号密码、2FA 或独立授权。未提供凭据的子号不能仅凭母号登录。

## 自动检查与角色识别

保存成功并不代表额度已经检查成功。现在保存后会创建可恢复的后台任务，依次识别官方身份、安排额度检查和母号成员同步。工作台显示后续进度，账号列表自动更新，通常不需要再点击刷新额度。

仅以授权对应的精确 Workspace ID 和官方读取到的角色判断母子号；Team 套餐本身、邮箱后缀、个人工作区里的 Owner 身份均不用于推断母号。已有团队的母号冲突、停用、已移除关系不会被自动覆盖。

暂时读取失败会有限重试，重启后安全恢复；额度刷新沿用现有队列与限流。网络失败或角色不明会显示原因，不把未完成检查标成成功。这个流程不启用自动轮转、邀请或其它全局自动化。

## 代理选择

- 自动：先使用账号已绑定的固定代理，再使用按邮箱匹配的母号代理，最后使用系统默认出口。系统默认未配置代理时，未匹配的账号使用服务器直连，表单会显示说明。
- 继承指定母号代理：选择母号团队，或按已同步成员匹配；母号缺少代理、所属团队不唯一时，显示失败原因，不回退直连。
- 代理档案、自定义代理、系统默认出口、服务器直连：用于明确指定出口。已有固定代理与所选出口冲突时停止该账号，不覆盖已有绑定。
- 不同出口分组调用授权桥，同一出口组按选择的并发执行。成功导入时冻结实际使用的代理，供后续本地任务使用。
- “本机代理端口”在完整工作台中指运行 Team48 的服务器，不是访问网页的电脑。

## 工作台自动保存

完整工作台顶部的「授权成功后自动保存到 Team48」默认开启，也可关闭。只保存本次协议登录成功的账号，不会扫描并自动导入浏览器中的所有旧记录，不自动上传密码或 2FA 密钥。

已有账号优先匹配它当前使用的工作区；新账号匹配已知团队。结果有多组无法唯一选择的授权、缺少原来已有的刷新令牌、正在执行其它凭据任务，或刷新权由远端托管时，不自动覆盖。页面会保留原因，可以点击「保存结果到 Team48」手动核对工作区。

保存时保留已有账号代理；已匹配团队且未绑定代理的子号继承母号代理，供后续本地管理任务使用。母号出口无法解析时显示原因，不默认为直连。

网络中断时，结果仍保留在浏览器工作台。使用「重试自动保存」或手动保存；重复提交同一组授权不会重复更新凭据版本。该重试仅在当前页面保留，关闭页面后可从手动保存入口读取工作台结果。

手动保存 2FA 仍需原有明确确认。同步和匹配只改变本地关系，不发送邀请、不移动成员、不修改 iCloud 标签、不推送远端账号。
